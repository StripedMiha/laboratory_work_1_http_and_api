# Мок SampleAPIs Coffee

Локальная замена https://api.sampleapis.com/coffee на случай, если публичный API недоступен,
перегружен или нужно показать сбои. Нужен только Python 3.10+; сторонние пакеты не используются.

```bash
python mock_server/server.py                 # http://127.0.0.1:8000/coffee/hot
python mock_server/server.py --port 9000 --host 0.0.0.0
```

В клиенте достаточно поменять базовый URL:

```python
client = SampleApisCoffeeClient(base_url="http://127.0.0.1:8000/coffee/hot")
```

Данные хранятся в памяти: каждый перезапуск возвращает их к снимку `data.json`
(коллекции `hot` и `iced`, снятые с реального API 5 октября 2026 года, включая чужие
«мусорные» записи вроде `id: "number"`). Свой снимок можно передать через `--data файл.json`.

## Что повторяет мок

Все пункты сверены с реальным API пробными запросами.

| Запрос | Ответ |
| --- | --- |
| `GET /coffee/{c}` | `200`, массив, заголовок `X-Total-Count`; `/coffee/{c}/` — то же самое |
| `GET /coffee/{c}/{id}` | `200` и объект; нет записи — `404` и `{}` (с JSON `Content-Type`) |
| `POST /coffee/{c}` | `201`, объект с `id`, заголовок `Location: /coffee/{c}/{id}` |
| `PUT /coffee/{c}/{id}` | `200`, объект целиком заменён; `id` берётся из URL, `id` в теле игнорируется |
| `PATCH /coffee/{c}/{id}` | `200`, изменены только переданные поля, `id` в теле игнорируется |
| `DELETE /coffee/{c}/{id}` | `200` и `{}` (не `204`); повторный DELETE — `404` и `{}` |
| неизвестная коллекция | `404` и `{}` |
| неподдерживаемый маршрут | `404` и `{"error":404,"message":"Cannot POST /coffee/hot/2"}` |

Правила, которые проверяет сервер:

- **POST и PUT**: тело — объект, в нём есть все поля «ожидаемой формы», кроме `id`
  (`title`, `description`, `ingredients`, `image`). Типы и значения **не проверяются**
  (`title: 5`, `ingredients: "E"`, пустые строки проходят), лишние поля сохраняются.
  Иначе `400` с `message`, `expected` (форма первой записи коллекции) и `received`.
  PUT сначала проверяет тело, потом наличие записи: неполное тело на отсутствующий `id` — `400`.
- **PATCH**: тело — непустой объект только из известных полей. Неизвестное поле или `{}` —
  `400` с сообщением «It appears you are trying to manipulate data…». Типы не проверяются.
- **Некорректный JSON** — `400` и `{"error":400,"message":"Something went wrong handling that request."}`.
- **Без `Content-Type: application/json`** тело как JSON не разбирается: для
  `application/x-www-form-urlencoded` вся строка становится ключом с пустым значением
  (в `received` это хорошо видно), поэтому POST получает `400`.
- **Выдача `id`**: «максимальный целый `id` + 1», строковые `id` не учитываются. Поэтому `id`
  удалённой последней записи выдаётся снова. Если в теле POST передан `id`, используется он;
  занятый `id` — `400` с описанием конфликта (см. ниже).
- **Поиск записи по `id`** — строковое сравнение, как в json-server: `/hot/number` находит
  запись с `id: "number"`, а `/hot/02` не находит запись с `id: 2`.

Параметры списка (как в json-server): `поле=значение` (точное совпадение с учётом регистра),
`поле_like=regex` (без учёта регистра), `поле_ne=значение`, `q=текст` (поиск по всем полям),
`_sort=поле&_order=asc|desc`, `_start`/`_end`/`_limit`, `_page`/`_limit` с заголовком `Link`.
`X-Total-Count` — число записей после фильтров, до пагинации.

## Чем мок отличается от реального API

- POST с уже занятым `id` в моке даёт `400` и
  `{"error":400,"message":"A record with id 2 already exists. Omit id from the request body to let the server assign one.","received":{...}}`;
  запись не меняется. Занятость проверяется по строковому виду `id`, поэтому `"2"` тоже
  конфликтует с `2`. На реальном API это не проверялось, чтобы не испортить чужие данные.
- Некорректный regex в `_like` даёт `400`; реальный сервер в этом случае не отвечает.
- OPTIONS отвечает `204` с CORS-заголовками; реальный сервер не отвечает.
- Нет HTTPS, лимита запросов (`RateLimit-*`) и заголовков Cloudflare. Ответы с ошибками
  других видов (5xx от прокси и т. п.) появляются только через `--fault`.

## Имитация сбоев

Флаг `--fault МЕТОД=ВИД` можно повторять; `*` вместо метода — все методы.

| Вид | Что происходит | Что показывает |
| --- | --- | --- |
| `slow` | ждёт `--slow-seconds` (по умолчанию 30), **потом выполняет запрос** | тайм-аут клиента; при POST запись создаётся, хотя клиент ответа не получил |
| `html` | `200` с `Content-Type: text/html` | проверку `Content-Type` до `.json()` |
| `500` | `500` с JSON-телом | обработку ошибок сервера |
| `502` | `502` с HTML-телом, как от прокси | ошибку, тело которой нельзя разбирать как JSON |
| `drop` | закрывает соединение без ответа | сетевую ошибку (`ConnectionError`) |

```bash
python mock_server/server.py --fault POST=slow --slow-seconds 15   # больше тайм-аута клиента (10 с)
python mock_server/server.py --fault GET=html
python mock_server/server.py --fault PATCH=502 --fault DELETE=drop
```

Сценарий `POST=slow` удобен для вопроса «можно ли повторить POST после тайм-аута»: после
ошибки клиента запрос `GET /coffee/hot?title_like=<метка>` показывает, что запись всё-таки
создана.

## Тесты

```bash
python -m unittest discover -s mock_server -v
```

Тесты используют только стандартную библиотеку. Последний тест прогоняет эталонный
`../solution.py` против мока; без установленного `requests` или файла он пропускается.

Клиент студентов дополнительно проверяется pytest-ом в `src/tests/test_client_mock_server.py`.
